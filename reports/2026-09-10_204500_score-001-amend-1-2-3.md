## Why this amendment exists

Josh's pre-merge review of PR #76 (2026-09-10 16:24 UTC) surfaced
three real concerns in the original SCORE-001 implementation:

1. **Fail-OPEN on invalid indicator data.** `_score_components`
   silently substituted 0 for any NaN/missing input, and
   `_clamp_total_score(NaN) == 0.0`. A partial-NaN scenario (e.g.,
   bullish RSI/SMA/BB with NaN MACD) could let the other components
   sum to 100 and trigger a BUY. The published 0 score from
   fully-invalid data also surfaced as a misleading "extreme
   bearish" value in any downstream reader.
2. **Under-documented post-multiplier bound.** The PR documented
   "components are clamped to ±25" but the volatility-tier 1.3x
   multiplier extends the AUTHORITATIVE post-multiplier bound to
   ±32.5 for RSI (low-vol) and SMA (high-vol). The original 56 tests
   only covered the pre-multiplier ±25 helper output; no test
   verified the post-multiplier envelope.
3. **Under-disclosed collateral changes.** The MTF `buy_criteria[0]
   ['passed']` "Score ≥ 65" check now passes for moderate-bullish
   setups that previously failed the signed-vs-65 check (the prior
   code labeled a signed value with "/100"). And the "MEDIUM SELL"
   branch is algebraically unreachable in both pre- and post-SCORE-001
   (`blended_signed <= -50` implies `blended_signed <= 20`).

## Amend #1 — Fail-closed on invalid / non-finite data

### New helper

`SmartTradingBot._is_finite_number(value)` is the single source of
truth for "is this a valid real number that can participate in score
math?" It returns True only for finite real numbers; NaN, inf, None,
unparseable strings, bool (subclass of int, rejected for safety), and
other objects return False.

### `_score_components` rewrite

Returns `None` if ANY of the following is non-finite, missing, or
fails-closed:

- RSI
- SMA fast (`SMA_{sma_fast}`)
- SMA slow (`SMA_{sma_slow}`)
- MACD_histogram
- ATR (must also be strictly positive; 0 makes the MACD ratio
  undefined)
- BB_upper
- BB_lower
- close (used for BB position)
- catalyst_score (the validated catalyst bonus)

The helper no longer silently substitutes 0. If the underlying
indicator data is invalid for any reason, the helper returns `None`
and the calling code aborts with `return None` so the symbol is
treated as non-actionable.

### `_clamp_total_score` rewrite

Returns `None` for NaN, inf, None, unparseable string, or
non-numeric input. Returns the clamped value (0..100) only for
finite real numbers. Callers MUST check the return.

### Caller updates

`analyze_symbol()` and `analyze_multi_timeframe()` both:

1. Call `_score_components(latest, catalyst_score=...)` early in the
   function.
2. If the helper returns `None`, log a debug line and `return None`
   (matching the existing "no data" pattern at the top of
   `analyze_symbol`).
3. Each subsequent `_clamp_total_score(...)` call is also None-checked
   and aborts with `return None` if the clamp returns `None` (so
   a NaN that slipped past the helper doesn't produce a published
   score).

The volatility-tier multiplier block, the hourly-blend block, and
the insider-trading +10 boost each honor the same None contract.

## Amend #2 — Post-multiplier bounds

### Authoritative documented bounds (POST-multiplier, PRE-final-clamp)

| Component | Pre-multiplier (helper) | Post-multiplier (`analyze_symbol`) | Worst case |
|---|---|---|---|
| RSI | ±25 | ±32.5 (low-vol `atr_pct < 2.0` only) | ±32.5 |
| SMA | ±25 | ±32.5 (high-vol `atr_pct > 5.0` only) | ±32.5 |
| MACD | ±25 | ±25 (no multiplier) | ±25 |
| BB | ±25 | ±25 (no multiplier) | ±25 |
| Catalyst | 0..+25 | 0..+25 (no multiplier) | 0..+25 |

### Worst-case envelope (math, verified by test)

```
Bullish raw signed sum: 32.5 + 32.5 + 25 + 25 + 25 = +140
  → clamp(50 + 140) = 100  (published max)

Bearish raw signed sum: -32.5 + -32.5 + -25 + -25 + 0 = -115
  → clamp(50 - 115) = 0    (published min)
```

The post-multiplier 1.3x multiplier is applied to the helper's
`rsi_score` (only when `atr_pct < 2.0`, low-vol) or `sma_score`
(only when `atr_pct > 5.0`, high-vol) — never both at once in
practice. The envelope tests verify the math at the documented
extreme; in normal operation the multiplier affects only one
component at a time.

## Amend #3 — Collateral disclosures

### 3A. MTF "Score ≥ 65" behavior change

Pre-SCORE-001 MTF total_score was a signed value (range roughly
-185..+135) with a "/100" display label. The check
`bool(total_score >= 65)` was internally inconsistent (signed vs
0..100-style threshold). Post-SCORE-001 MTF total_score is genuinely
in 0..100, and the check is now consistent.

**Net effect: moderate bullish MTF setups that previously failed the
signed-vs-65 check (e.g., signed value ~25) now pass the
0..100-vs-65 check (published value ~65+).** This is a documented
collateral behavior change from the SCORE-001 scale fix; it is not
hidden as "no semantic change."

The buy_criteria display is now honest: `Score: 65/100` actually
means 65 out of 100, not "signed value 65 with a misleading
label."

### 3B. MEDIUM SELL unreachable (pre-existing bug, preserved)

The SELL branch in `analyze_symbol`:

```python
elif blended_signed <= -50:
    signal = "SELL"
    if blended_signed <= 20:
        signal_strength = "STRONG"
    else:
        signal_strength = "MEDIUM"  # unreachable
```

Algebraically, `blended_signed <= -50` already implies
`blended_signed <= 20`, so the "MEDIUM SELL" branch is unreachable
in BOTH the pre- and post-SCORE-001 code. All SELL signals are
STRONG.

This is a pre-existing bug that SCORE-001 deliberately preserved
per the user spec: "If a threshold change appears necessary, STOP
and report before changing it." Fixing MEDIUM SELL would require
either:

- Redefining the MEDIUM SELL range on the 0..100 scale (e.g., when
  `total_score` is in [20, 50]), which is a threshold value change;
  OR
- Re-deriving a separate MEDIUM SELL condition on `blended_signed`
  (e.g., `-50 < blended_signed <= -25`).

Both are deliberate threshold changes that warrant a separate
backlog item. A future iteration (e.g., SCORE-003) should pick up
this work.
