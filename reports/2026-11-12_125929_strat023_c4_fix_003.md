## 1. The defect

On 2026-11-11 the STRAT-024 paper runner opened XOM (fill 2026-11-11, 64 sh,
entry price 164.924062, ATR14 5.158707142857147). The entry-day close was
166.71, above the SMA5 of 165.416, so the runner:

1. canceled the resting 3xATR protective stop `sl_short-XOM-s-20261110`
   (Alpaca order `bac82e45`, stop 149.45), and
2. submitted an SMA5 market sell `sl_short-XOM-xsma5-20261111`
   (Alpaca order `5ef4f1a6`).

The SMA5 exit order was later canceled at the broker (5:57:55 AM CST), so the
position was left holding 64 shares with **no** protective stop and **no**
exit order — unprotected.

Two root causes:

* **Entry-day SMA5.** The runner evaluated `close > SMA5` on the *latest*
  bar, which on the fill date IS the entry bar. The frozen C4 rule is
  `s > entry_i`: the SMA5 exit is only valid on a bar STRICTLY AFTER the
  entry bar. The entry day must also come from the entry fill
  (`positions.entry_date`, fallback: the entry order's `filled_at` DATE),
  never from `signal_date` (the signal day is the day BEFORE the fill).
* **No re-protection.** Nothing restored the 3xATR stop when the exit order
  died, and nothing restored it when the broker no longer knew the stop.
  A canceled stop row also stayed `status='submitted'` in the local DB.

## 2. Changes (`experiments/strat_023/live_paper_runner.py`)

### 2.1 Entry-day SMA5 suppression
* The entry day is `positions.entry_date`, falling back to the entry
  order's `filled_at` date. `signal_date` is never used.
* Every bar STRICTLY AFTER the entry bar is scanned; the FIRST breach wins
  (the bar the backtest would have exited on). A missing session can never
  suppress a later SMA5 exit.
* The ATR protection stays a RESTING 3xATR stop. No close-based ATR market
  exit was added.

### 2.2 Stop restoration / reconciliation
* `working_order_exists(symbol, kinds)` — an order counts as working only
  when the broker still reports a pending status (`new`, `held`, `accepted`,
  `pending_new`, `partially_filled`). A broker hiccup is treated as
  "working" so a transient error never places a duplicate protective stop.
* Every open position that still holds shares and has **neither** a working
  exit **nor** a working stop gets a NEW 3xATR stop placed
  (`summary["stops_replaced"]`).
* A canceled stop's LOCAL row is marked `status='canceled'` in the same
  pass (it never stays `submitted`).
* While a position is open, `exit_date` / `exit_reason` are cleared — a
  canceled/expired/rejected exit is not an exit.
* An exit order that is already working for the position is never
  duplicated, and an exit for the same session is never re-spammed.

### 2.3 Replacement-stop id derivation
* `unique_coid(symbol, kind, ref_date, attempt)`:
  attempt 1 = the historical deterministic id
  `sl_short-<sym>-<kind>-<yyyymmdd>`; attempt N>1 appends `-rN`
  (`sl_short-XOM-s-20261110-r2`), truncated to `COID_MAX`.
* `fresh_coid()` picks the first attempt whose id is NOT already known
  locally (any `orders` row, whatever its status — filled, canceled,
  expired, rejected) and is not an open broker order. A known id is NEVER
  reused, so Alpaca can never reject the replacement as a duplicate.

## 3. Tests

New file `experiments/strat_023/test_c4_fix_003.py` (11 cases) proves:
1. the entry-day close above the SMA5 does NOT exit and the stop stays;
2. the first post-entry session breaches the SMA5 -> exit submitted, the
   stop canceled and its local row marked `canceled`;
3. the entry day comes from `entry_date`, not `signal_date`;
4. a MISSING session between the entry bar and the breach does not suppress
   the exit;

## 6. Residual risks

* The restored stop uses the position's recorded `entry_price` and
  `signal_atr14`; if the live row lacks them, no stop is placed (the
  position is then reported as unprotected rather than silently protected
  with a guessed price).
* A broker outage is treated as "order still working" — the runner will not
  place a replacement stop while the broker cannot be reached.
* The SMA5 exit still fills at the next open (documented divergence from
  the backtest), unchanged by this fix.
