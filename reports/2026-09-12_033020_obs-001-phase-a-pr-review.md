## PR Review Finding (Josh 2026-09-12 03:30 UTC)

### Issue: `finalize_decision_history` used UPSERT, not plain INSERT

The original SQL:
```sql
INSERT INTO decision_history
   (cycle_id, symbol, cycle_start, session_id,
    decision_schema_version, decision_snapshot)
VALUES (?, ?, ?, ?, ?, ?)
ON CONFLICT(cycle_id, symbol) DO UPDATE SET
    decision_schema_version = excluded.decision_schema_version,
    decision_snapshot = excluded.decision_snapshot
```

This is a silent UPSERT — a second call with the same (cycle_id, symbol)
would OVERWRITE the original finalized JSON. Josh's immutability
requirement was violated.

### Fix: plain INSERT + IntegrityError catch

```python
def finalize_decision_history(...) -> bool:
    """INSERT-only. UNIQUE(cycle_id, symbol) makes duplicate inserts
    fail with sqlite3.IntegrityError, which is caught and logged;
    the EXISTING finalized row is NEVER updated, replaced, or
    reinserted."""
    try:
        with _get_conn() as conn:
            cur = conn.execute(
                """INSERT INTO decision_history
                   (cycle_id, symbol, cycle_start, session_id,
                    decision_schema_version, decision_snapshot)
                   VALUES (?, ?, ?, ?, ?, ?)""",
                (...),
            )
            return cur.rowcount > 0
    except sqlite3.IntegrityError as e:
        # UNIQUE(cycle_id, symbol) violation: original row preserved.
        logging.debug(f"decision_history already finalized for "
                      f"{cycle_id}/{symbol} (original preserved): {e}")
        return False
    except Exception as e:
        logging.debug(f"Error finalizing decision_history: {e}")
        return False
```
