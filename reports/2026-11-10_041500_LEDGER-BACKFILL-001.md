## 1. Executive summary

Two deliverables:

1. **`scripts/backfill_symbol_fills.py`** — a new PAPER-only tool that backfills
   broker-confirmed FILLED trades that are missing from the trading ledger, using
   REAL Alpaca PAPER order history. Dry run by default; a write requires BOTH
   `--apply` AND an explicit `--db`. Broker access is strictly read-only. A
   timestamped backup is taken before every write, and a post-write verification
   re-reads the ledger and proves the projected net equals the expected broker
   quantity. Swing-runner fills are excluded fail-closed.
2. **`src/core/smart_bot.py`** — `_broker_position_qty()` now compares symbols
   case-insensitively and whitespace-tolerantly. Previously a broker reporting
   `Aaa` where the caller used `AAA` silently returned `0.0`, which the fail-closed
   SELL path reads as "broker bound unavailable" and uses to refuse a legitimate
   SELL.

Backed by `tests/test_ledger_backfill_001.py` (44 focused offline tests) and the
repository-wide suite (2403 passed; 1 known pre-existing environmental failure).

## 4. The `src/core/smart_bot.py` fix

The change normalizes BOTH the requested symbol and the broker-reported symbol:

```python
req = str(symbol or "").strip().upper()
...
b_sym = str(getattr(pos, "symbol", "") or "").strip().upper()
if not b_sym:
    continue          # an empty broker symbol must never match
if b_sym != req:
    continue
```

Behaviour contract:

| Case | Result |
|---|---|
| broker `AAA`, requested `AAA` | match |
| broker `Aaa`, requested `AAA` | match (case-insensitive) |
| broker ` AAA `, requested `AAA` | match (whitespace-tolerant) |
| broker `AAA`, requested `aaa` | match |
| broker symbol absent / empty | no match -> `0.0` |
| broker quantity missing | `0.0` |
| broker read raises | `0.0` (fail closed) |

Why it matters: the fail-closed SELL path treats `0.0` as "broker bound
unavailable". A case mismatch therefore blocked a legitimate SELL of a position
that genuinely existed. Swing-owned quantities are still never attributed to the
main bot, because the ownership bound comes from the bot's OWN FILLED ledger rows
(`_proven_own_qty`), independent of the broker bound.

### 5.1 Swing exclusion detail

`allocation_policy.DEFAULT_SWING_ORDER_LABEL_PREFIXES` is the single source of
truth for the prefixes (`sl_short-`, `rsi2-`).
`swing_runner_db_paths` DEFAULTS TO `[]`, which disables DB attribution, so
LABEL attribution is the DEFAULT guard and runner-DB attribution is the
supplement. A fill is excluded when either matches.

### 5.2 Reconciliation uses the bot's own ownership math

`verify_projection()` calls
`allocation_policy.own_net_qty_from_ledger_rows()` over
(existing ledger rows + planned rows). Confirmed semantics:

- only `status == 'FILLED'` rows with a `filled_qty` count prove ownership
  (SUBMITTED / REJECTED / CANCELED prove nothing);
- BUY adds, SELL subtracts; sleeve tags are ignored; symbols are uppercased;
- net quantities resolving to approximately zero are excluded;
- malformed rows are skipped fail-closed.

Any mismatch is a DISCREPANCY: nothing is written and the tool refuses to guess.
It offers the documented `--expect SYM=QTY` override or narrowing `--symbols`.

### 5.3 The inserted row shape

Mirrors `scripts/reconcile_ledger_with_broker.py` / EXEC-004:

- `sleeve = 'S'`
- `status = 'FILLED'`
- `filled_qty` = the REAL broker filled quantity
- `avg_fill_price` = the REAL broker average fill price
- `price` = the same real average fill price
- `broker_order_id` = the real broker order id (the idempotency key)
- `pnl` = NULL (never fabricated)
- `notes = 'LEDGER-BACKFILL-001: broker-authoritative backfill from Alpaca paper fill history'`

The `notes` marker means a backfill row can never be confused with a live
submission.

## 11. Known risks

1. **The tool has never been exercised against the REAL Alpaca PAPER API.** Every
   test used a fake broker. The PAPER endpoint guard, the real order-payload
   shape from Alpaca v2, and the real `filled_avg_price`/`filled_qty` field
   names are UNVERIFIED against the live PAPER API. A first run against real
   PAPER must be a DRY RUN (the default) and its output inspected before any
   `--apply`.
2. **The production ledger was never opened.** The tool's default runner DB is
   `/root/strat-swing/experiments/strat_023/live_paper.db` (read-only). The
   production trading DB (~32GB) was neither read nor written by any command in
   this task; its `trades` schema was confirmed separately from the migration
   (`src/database/sqlite_db.py`), not from the live file.
3. **`swing_runner_db_paths` defaults to `[]`.** DB attribution is therefore OFF
   by default; only label attribution (`sl_short-`, `rsi2-`) protects the main
   bot. This is why the AAAA order ids being absent from the runner DB is safe
   today — but a swing fill with a NON-standard label would NOT be excluded by
   label, and DB attribution is off. Any future change must keep the quantity
   reconciliation as the backstop (it did refuse AAAA here).
4. **The RSI(2) runner has no usable attribution source.** `swing_runner_db_paths`
   contains no RSI(2) DB, and the RSI(2) `state.json` contains unfilled dry-run
   shadow entries that must not be trusted for attribution. RSI(2) exclusion is
   therefore label-only (`rsi2-`).
5. **A `pnl` of NULL on backfilled rows** is correct (never fabricate), but any
   downstream report that sums `pnl` without a NULL guard will need attention.
6. **`--expect SYM=QTY` is an explicit override** of the reconciliation. It is
   documented, but it bypasses the fail-closed quantity check and therefore
   needs the same human review as an `--apply`.
7. **The case-insensitive fix changes a fail-closed guard's inputs.** It makes
   the broker bound MORE likely to be non-zero, which un-blocks SELLs that were
   previously refused. The ownership bound (`_proven_own_qty`, ledger-proven)
   still governs the SELL quantity, so swing shares remain unsellable by the main
   bot; but the change does widen the set of SELLs that can proceed, so the
   EXEC-004 / REBAL guard suites were re-run (132 passed) and the full suite
   shows no new failure.
