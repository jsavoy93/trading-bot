## 1. Executive summary

Three storage-only controls reduce the append-only growth of `decision_history`
and its normalized child tables. No trading behavior is changed: no BUY/SELL
threshold, score, eligibility gate, ranking, sizing, slot semantic, risk rule,
brokerage call or order-handling path was touched.

1. **Unchanged-HOLD suppression** — a plain `HOLD_INELIGIBLE` decision whose
   observable state is unchanged versus the LAST persisted `decision_history`
   row for that symbol is not written again. There is **no same-day heartbeat
   exception**. BUY, SELL and every other non-HOLD outcome are always
   persisted in full.
2. **Closed-market write suppression** — while the US equity market is closed,
   the per-symbol `decision_history` row and its `decision_gate_evaluations` /
   `decision_execution_checks` children are not written. The `analyzed_stocks`
   latest-state upsert and `cycle_funnel` handling are unaffected.
3. **Retention pruning with a verified gzip JSONL archive** — rows older than
   the retention window (default 30 days) are deleted in small batches,
   children first, parents second, restricted to those three tables only. The
   parents are archived to a gzip JSONL file (one JSON object per line, all
   columns) BEFORE the delete; the archive is written, closed and read back,
   and its line count is verified against the deletion-candidate count. A write
   failure or a count mismatch keeps the rows and records the error.

## 2. Task / purpose

`decision_history` grows without bound: every cycle writes one parent row per
symbol plus normalized child rows, including many identical HOLD observations.
The task was to add observability-only growth controls that keep the data
useful (BUY/SELL/state changes/order attempts always recorded) while removing
the redundant volume, and to delete expired rows safely with a verifiable
archive.

Explicitly out of scope and unchanged: trading thresholds, scores, eligibility
gates, ranking, sizing, slot semantics, risk rules, brokerage behavior, order
handling, `decision_history` immutability and its `UNIQUE(cycle_id, symbol)`
constraint.

## 8. Design / safety notes

- **Fail-safe everywhere.** Any lookup, comparison, calendar or clock error
  results in the FULL decision row being written (`_should_suppress_decision_row`
  and `_decision_history_writes_allowed` both catch and default to "write").
- **Fail-safe in the prune.** The archive is written and verified BEFORE the
  delete; a write failure or a line-count mismatch keeps the rows and records
  the error. Deleting data that was not archived is never possible.
- **Immutability preserved.** `decision_history` stays insert-only with its
  `UNIQUE(cycle_id, symbol)` constraint; `finalize_decision_history` and its
  parent+children transaction are untouched.
- **Small batches.** The prune deletes at most `decision_history_prune_batch_size`
  (default 5000) parents per write transaction; the gzip write happens OUTSIDE
  the SQLite write transaction so the write lock is never held during it.
- **Timestamp robustness.** The retention cutoff is a UTC ISO timestamp
  (`datetime.now(timezone.utc) - timedelta(days=retention_days)`); candidate
  selection compares `julianday(cycle_start) < julianday(?)` so rows mixing
  `+00:00` and `Z` formats are handled, with a string-comparison fallback for
  unparsable timestamps (so they cannot become immortal).
- **Archive format.** gzip JSONL, one JSON object per line, ALL columns of the
  parent row, named `decision_history_<UTC timestamp>.jsonl.gz`.
- **Relative archive dir** resolves against the repository root
  (`Path(__file__).resolve().parents[2]`), so the archive always lands in the
  same place regardless of the process working directory.
- **Prune hook placement.** `_maybe_run_retention_prune()` is called at the top
  of a continuous-loop iteration, outside every per-symbol decision, and is
  guarded by "market closed" + "once per NY calendar day" (tracked in
  `self._last_retention_prune_date`). Any exception is logged and swallowed so
  a retention job can never crash the trading loop.
- **Child deletion order.** `decision_gate_evaluations` and
  `decision_execution_checks` are deleted BEFORE the `decision_history`
  parents; both reference the parent through `decision_history_id`.

## 9. Known risks

1. **Suppression hides slow drift.** A HOLD whose observable state stays
   identical is no longer re-recorded each cycle. The retained row is the
   latest state; `analyzed_stocks` still carries the current snapshot on every
   cycle, so "latest" is not lost — only the append-only trail is thinned.
   `decision_snapshot_score_tolerance` (default 1.0 point) is the knob for
   how much score movement counts as a change.
2. **Closed-market writes are dropped entirely.** While the market is closed,
   no per-symbol `decision_history` row exists for that period. This is the
   intended trade-off of the requested control; `decision_history_market_hours_only`
   turns it off.
3. **Archive growth.** The gzip archive is never rotated or deleted by this
   change. `research_data/db_archive` grows with the pruned volume and must be
   garbage-collected by an operator policy that does not exist yet.
4. **Archive location on the production host.** The default
   `research_data/db_archive` is inside the repository tree and is
   `.gitignore`d (`*.db` does not cover `.jsonl.gz` — the directory should be
   confirmed ignored or moved outside the repo before the first production
   prune).
5. **Pre-existing environmental suite failure** (`test_units_not_installed`)
   remains red on this host; it is unrelated to this task and was already
   documented in `MAP.md`.
6. **Pre-existing schema drift** (observed while testing, NOT introduced and
   NOT fixed here): `save_analysis_result` fails on a fresh schema with
   `table analyzed_stocks has no column named buy_criteria`, so the
   `analyzed_stocks` upsert silently no-ops on databases created from the
   current `CREATE TABLE` statements. The closed-market test therefore
   asserts the upsert via a spy rather than via a row count. Fixing that
   drift would change the schema and is out of scope for DB-GROWTH-FIX-3; it
   should be raised as its own task.
