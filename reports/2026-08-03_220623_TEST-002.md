## Oracle investigation

The previous focused run failed on the first mismatching MACD assertion in
each price-pattern case:

| Case/field | Expected | Actual | Absolute difference | Relative difference |
|---|---:|---:|---:|---:|
| Bullish `MACD_signal` | 6.8049759701286101 | 6.8049755894315318 | 3.8069707830601374e-07 | 5.5943926911297937e-08 |
| Neutral `MACD` | 0.055078625434094031 | 0.055079436469796406 | 8.1103570237495148e-07 | 1.4725053430126363e-05 |
| Bearish `MACD_signal` | -6.8049759701286128 | -6.8049755894315744 | 3.8069703833798485e-07 | 5.5943921037944494e-08 |

Production implements MACD(12,26,9) with pandas
`ewm(span=12/26/9, adjust=False)`, recursively initialized from the first
value. A separate 50-digit Decimal recurrence using alpha `2/(span+1)` matched
production within `1.1e-14` to `2.6e-14`. The incorrect expectations had been
copied beyond the precision of a six-decimal exploratory display. This was an
incorrect oracle, not `adjust=True`, warm-up behavior, meaningful floating-
point drift, or a production defect. Only the test MACD constants and tolerance
were corrected; production remained untouched.
