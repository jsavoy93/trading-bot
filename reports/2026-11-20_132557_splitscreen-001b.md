## Finding 1 — the first run's cleaning was incomplete

The v1 repair loop (repair.py) iterates at most 25 times per symbol and, because a
"Q" (full-series) correction does not readjust the flagged ratio to 1.0, re-detects
the same day on every pass and burns the budget. Effect: symbols with more than one
big move lost their later corrections.

Verified on BHVN:
- Raw panel 2022-10-03 151.80 -> 2022-10-04 8.30 (ratio 0.0547, the 1-for-20
  reverse split).
- panel_clean.parquet (v1): 151.80 -> 8.30 — unchanged. The artifact survived.
- repair.classify() on that day returns 'Q', so it *should* have been corrected;
  the loop never reached it.

Also affected: a second BHVN step 2022-05-10 (140.00 -> 235.75), and the whole
class of multi-event tickers. The v1 flag list (24 DEV events) is therefore an
under-count; a vectorized re-scan finds 3,678 candidate events in DEV.

## Finding 2 — v2 panel built

Built /root/research/splitscreen-001/panel_clean_v2.parquet from panel_clean.parquet
(the v1 file, itself the repaired source) with a fresh vectorized adjustment:

1. Vectorized classify() over every symbol (no per-symbol Python loop):
   8,717 candidates on <=2024-12-31 data, 6,837 in DEV (245 'P', 6,592 'Q').
2. Churn guard: symbols with >6 same-direction DEV flags are dropped (226 symbols).
3. Remaining 3,678 events applied by numpy slice arithmetic, latest first:
   f = close[t]/close[t-1]; rows strictly before t are multiplied by f (open,
   close) and divided by f (volume). Slices are written with slice objects
   (a read-only-view bug in an earlier attempt silently skipped every write and
   is the reason for the extra verification passes below).
4. All 3,325 events that exist in the panel were applied; 0 skipped.
