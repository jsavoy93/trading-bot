## Problem 1 — same-run sleeve sizing
The runner sized every candidate of a run against a stale pending-notional
value, so three qualifying C4 signals in ONE run could each take the full
10% per-name cap (30% committed against a 15% sleeve).

Fix: `experiments/strat_023/live_paper_runner.py` now adds `qty × price`
to the run's pending notional immediately after each entry submission.
Same-run committed + pending notional stays <= 15% of equity and no
single entry exceeds 10%. Unchanged: `SLEEVE_EQUITY_FRAC=0.15`,
`MAX_POSITION_PCT=0.10`, `MAX_POSITIONS=3`, all entry/exit rules and
thresholds (ENTRY_RSI=10, ATR_MULT=3.0, TIME_STOP=10, WARMUP_BARS=220).

## Problem 2 — missing exit prices / exit bookkeeping
Exit and stop orders stayed `submitted` forever and the position was
closed without the real fill: no `exit_price`, no fill time, no P&L.

Fix:
- `reconcile_exit_orders()` runs BEFORE the broker-position-zero branch.
  Filled exit/stop → order `filled`, position `closed` with the broker
  `filled_avg_price`, `exit_date`/`exit_time` from `filled_at`, retained
  exit reason and `realized_pnl`. Canceled stop → order `canceled`.
  `new`/`held`/`accepted`/`pending_new`/`partially_filled` → left pending.
  Missing broker order → left pending, no crash, no invented fill.
- `positions` gained `exit_time TEXT` and `realized_pnl REAL`, added in
  place by `open_db()` via a `PRAGMA table_info`-guarded migration.
- Run summary now reports `exit_fills` next to `fills_tracked`.
