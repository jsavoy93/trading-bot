## 1. Root cause (from Phase 1 audit, read-only)

alpaca-py 0.43.4 `Asset.exchange: AssetExchange` enum has no `TXSE` member.
Alpaca started returning exchange=TXSE on 2026-10-19, so strict
`TypeAdapter(List[Asset])` validation of the whole assets response raised
`pydantic.ValidationError`. `get_all_us_symbols()` (src/core/smart_bot.py,
~line 1325) caught it in a catch-all and returned `[]`. The rolling universe
drained to zero symbols by 2026-10-20 19:11 UTC. Positions/SELL/risk controls
unaffected (they do not use get_all_assets).

Audit archive read:
`/root/.openclaw/audit-archives/trading-bot/2026-10-21_140848_txse-outage-verification.md`.

## 2. Upstream dependency check (report only, NO upgrade made)

`pip index versions alpaca-py` -> latest 0.44.0; available 0.43.5, 0.44.0.
Inspected the AssetExchange enum inside the downloaded wheels:

- alpaca_py-0.43.5: `class AssetExchange(str, Enum): AMEX, ARCA, ASCX, BATS, NYSE,
  NASDAQ, NYSEARCA, FTXU, CBSE, GNSS, ERSX, OTC, CRYPTO, EMPTY` — NO TXSE.

Conclusion: upgrading alpaca-py would NOT fix the outage. No dependency change was
made. The per-asset skip approach is required for robustness against any future
new exchange value.

## 3. Implementation

Files changed: src/core/smart_bot.py, tests/test_universe_txse_resilience.py.

- `_build_asset_tolerant(raw_asset)` — builds a strictly-validated
  `alpaca.trading.models.Asset` from one raw record; FULL strict validation (no field
  relaxation). Documented UNIVERSE POLICY in its docstring: a single unknown
  exchange code must not disable the whole universe; records the SDK cannot model are
  skipped fail-closed; exchange validation is never globally disabled.
- `_fetch_assets_resilient()` — fast path `trading_client.get_all_assets()`
  (unchanged). Only on `pydantic.ValidationError` does it re-read the raw response via
  the SDK's own `trading_client.get("/assets")` (the same HTTP call the SDK makes
  before `TypeAdapter(List[Asset])`) and validate asset-by-asset. Skipped records are
  counted and a bounded sample (up to 3, plus "+N more") is logged at WARNING. If the
  client exposes no `.get`, the original strict error is re-raised (fail-closed).
- `_describe_validation_failure(exc, raw)` — summarizes WHY a record was skipped,
  naming the unmodelled field(s) and the reported exchange value.
- `get_all_us_symbols()` — now calls `_fetch_assets_resilient()`; the per-asset
  eligibility loop is byte-identical to main; adds a WARNING when a non-empty asset
  list filters to zero US equity symbols. The outer catch-all still logs
  `❌ Failed to get symbols` at ERROR and returns [] for genuine request-level
  failures (HTTP/auth/network) — never silently empty.

### Filter-predicate diff (must be ZERO changes)
`git diff` grep for tradable/AssetStatus/AssetClass/asset.symbol in changed lines
returns NO matches. The eligibility predicates
(`asset.tradable and str(asset.status)=='AssetStatus.ACTIVE' and
str(asset.asset_class)=='AssetClass.US_EQUITY'`) and the inner per-asset exception
fallback are byte-identical to main. No risk/liquidity/shortable filter was touched.

### Documented policy for unknown exchanges (summary)
An asset record that the installed alpaca-py cannot model (most likely a new broker
exchange code such as TXSE) is SKIPPED from the universe fail-closed — never partially
trusted, never globally relaxed — and reported with a skip count and bounded sample so
the universe-completeness impact is observable. Until alpaca-py ships TXSE, TXSE-listed
symbols are absent: a bounded, logged completeness gap rather than a total outage.
Genuine request-level failures remain loudly surfaced at ERROR.

(2026-10-21) across the whole broker response — i.e. the completeness gap is on the
order of single digits (well under 0.1% of the universe), fully logged.
