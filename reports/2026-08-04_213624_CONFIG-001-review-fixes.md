## Review findings addressed

### Blocking finding 1 — Dashboard batch updates could partially persist
Fixed. `dashboard.py` now separates validation from persistence:
- `_normalize_dashboard_value()` coerces and validates one value without writing.
- `_validate_dashboard_settings_batch()` validates all known submitted settings and returns normalized values.
- `_persist_dashboard_settings_batch()` writes only after the full batch validates.
- `api_update_settings()` returns HTTP 400 on validation failure before any write.

Regression tests added:
- `test_dashboard_batch_with_invalid_value_persists_nothing`
- `test_dashboard_fully_valid_batch_persists_all_normalized_values`
- `test_dashboard_api_route_returns_http_400_for_invalid_schema_input`

### Blocking finding 2 — Some schema-backed settings were dashboard-visible but not consumed
Fixed for the reviewed settings:
- `atr_position_size_pct` is now an explicit bot attribute and derives the internal decimal `risk_per_trade` consumed by ATR sizing math.
- `loop_delay_seconds` now controls normal continuous-loop delay through `_resolve_loop_delay()` when no explicit delay is supplied.

Precedence documented and tested:
- Explicit caller argument `run_continuous_loop(..., loop_delay=...)` wins.
- CLI `--delay` wins because it is passed as an explicit loop delay.
- If no explicit delay is supplied, the effective schema-backed `loop_delay_seconds` value is used.

Regression tests added:
- `test_bot_consumes_effective_atr_position_size_pct_as_risk_sizing`
- `test_bot_loop_delay_uses_configured_value_when_no_explicit_argument`
- `test_bot_loop_delay_explicit_argument_overrides_configured_value`

## Invalid legacy-value handling
`settings_service.load_effective_strategy_settings()` now catches `ValueError` per schema key, logs a warning containing the invalid key and default, and uses the schema default for that key. Other valid persisted settings still apply. This prevents one legacy bad setting from blocking bot startup or dashboard settings rendering.

Regression tests added:
- `test_invalid_legacy_values_fall_back_to_schema_defaults`
- `test_bot_startup_with_invalid_legacy_setting_uses_default_safely`
- `test_dashboard_metadata_falls_back_for_invalid_legacy_values`

## Configuration precedence
1. Schema defaults in `STRATEGY_SETTINGS_SCHEMA`.
2. Persisted SQLite `settings` overrides, if each override is valid.
3. Per-key fallback to schema default for invalid legacy persisted values.
4. Smart bot constructor applies effective settings to matching runtime attributes.
5. For loop delay only: explicit method/CLI delay overrides configured `loop_delay_seconds`; absent explicit delay uses effective configuration.
6. For ATR sizing: `atr_position_size_pct` is the effective percent setting; `risk_per_trade` is the derived runtime decimal.
