## 1. Executive summary

The C4 short-term sleeve was a hard-coded 30% of account equity. S3 caps
it at a fixed **15%** of equity and makes the fraction configurable through
`STRAT024_SLEEVE_EQUITY_FRAC`. Everything else is untouched: the C4 signal
thresholds, the exit rules, the per-position cap (10%), the max open
positions (3) and all four safety guards are identical.

the C4 paper runner is not on `main` — it lives on

## 5. Known risks / uncertainties

1. **The sleeve fraction is read once at import time.** Changing
   `STRAT024_SLEEVE_EQUITY_FRAC` requires a new process. The systemd
   unit was NOT edited (no deploy), so a future run would use the default
   15% unless the env var is set in the unit file.
2. **A tighter sleeve suppresses entries.** With a 15% sleeve of a 100k
   account (15k) and a 10% per-position cap, the sleeve only binds when
   existing C4 exposure exceeds 15k. Positions opened under the old 30%
   sleeve can be **over** the new cap; the runner then simply stops
   adding new entries until the sleeve frees up. It never force-closes
   anything.
3. **The env var is read at import, so a bad value raises ValueError at
   process start** (fail loud by design) rather than silently falling back
   to 15%.
4. **The branch is stacked.** This PR must be merged after (or together
   with) `research/strat-023-c4-shadow`; it does not apply to `main`
   on its own because the C4 runner does not exist there.
5. **The 43 pre-existing failures of the base branch** are a branch-freshness
   problem, not a regression. Merging `research/strat-023-c4-shadow` into
   `main` first would clear them — that is a separate decision for Josh.
