## Bug

All order lookups in live_paper_runner.py used
`GET /v2/orders/{client_order_id}` (3 sites: fill polling ~L257,
time-exit entry check ~L319, pre-exit stop lookup ~L335). Alpaca's
`/v2/orders/{id}` path accepts ONLY the Alpaca order id; a
client_order_id there returns 404. Sites 1 and 3 wrapped the call in
`except Exception: order = None` → 404 silently meant "still pending".
Result: AMD/AVTR/CRL entries filled at the 2026-11-03 open but rows
stayed `pending_fill`, fills_tracked=0, no 3xATR stops placed, exit
engine unreachable, new entries blocked by MAX_POSITIONS=3 counting
pending_fill rows.

Live DB evidence (read-only, mode=ro):
```

AVTR| 2026-11-02 | atr 0.56232 | sl_short-AVTR-e-20261102| pending_fill
CRL | 2026-11-02 | atr 16.9819 | sl_short-CRL-e-20261102| pending_fill
orders: entry/submitted with alpaca_order_ids
1c2f5f29-… / 35a04df6-… / 75fcaf81-…
```

## Fix

1. `PaperAPI.get_order_by_client_id(coid)` — GET
   `/v2/orders:by_client_order_id?client_order_id=…`; 404 → None;
   429 → sleep+retry; 401/403 → fail(); anything else raise_for_status
   (fail loudly).
2. `PaperAPI.get_order(order_id)` — GET `/v2/orders/{alpaca_id}`;
   same error contract.
3. `run_once.lookup_order(c)` closure — client-id lookup first, then
   fallback to `orders.alpaca_order_id` from the local DB; None only
   when genuinely not found.
4. All three broken sites now use `lookup_order`; no silent
   `except Exception` remains on order lookups.
5. BUY thresholds / C4 strategy logic untouched (frozen imports from
   shadow_runner; test_c4_parameters_not_relaxed still passes).
