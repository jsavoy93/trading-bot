## 1. backfill_exit_prices.py dry-run counter (MUST-FIX)

The counter `written += 1` was inside `if apply:`, so a dry run always printed
"DRY-RUN: 0 position(s) WOULD be updated" even when it had just listed the
rows it would update. The increment was moved out of the `if apply:` block, so
both modes count the same rows:

* apply  -> "APPLIED: N position(s) updated"
* dryrun -> "DRY-RUN: N position(s) WOULD be updated (nothing was written)"

Extra safety: a position closed by a canceled ENTRY (`exit_reason='entry_canceled'`)
is excluded from the backfill scan — it never had an exit fill.

## 2. --db is REQUIRED (MUST-FIX)

`--db` used to default to `HERE/live_paper.db` (the live paper DB), so a bare
invocation could touch the live database. It is now `required=True`; a bare
invocation exits with the argparse usage error (exit code 2) and opens no
database. The new cleanup command has the same rule.

## 3. Canceled / expired / rejected ENTRY handling (live_paper_runner.run_once)

New module-level constants and helper in `live_paper_runner.py`:

* `TERMINAL_NOT_FILLED_STATUSES = ("canceled", "cancelled", "expired", "rejected")`
* `is_terminal_not_filled(status)`
* `mark_entry_canceled(conn, pid, coid, status, exit_date)` — closes the
  position row as canceled with NO P&L and stamps the orders row with the
  broker's terminal status. Idempotent (only touches 'pending_fill' rows).

In `run_once` section 1 (before the "status must be filled" check) a
terminal-not-filled entry order is now handled:

* partial fill (`filled_qty > 0`): the FILLED shares stay as the position
  (`status='open'`, `qty=filled_qty`, `entry_price=filled_avg_price`,
  `entry_date` from `filled_at`) and the normal 3xATR stop is placed for the
  FILLED quantity only (the stop placement was factored into `place_stop()`).
* zero fill: the position row is closed as canceled with NO P&L
  (`status='closed'`, `exit_reason='entry_canceled'`, `exit_price` NULL,
  `realized_pnl` NULL), which frees its MAX_POSITIONS slot and its sleeve
  notional; the orders row carries 'canceled' / 'expired' / 'rejected'
  instead of 'submitted'.

The strict fill quantity is used on purpose: `filled_qty=0` must never fall
back to the ORDERED quantity.

## 4. One-off batch command: cleanup_canceled_entries.py (new)

`python -m experiments.strat_023.cleanup_canceled_entries --db <path> [--apply]`

* `--db` REQUIRED (no default) and an explicit `--apply`; the dry run is the
  DEFAULT and writes NOTHING (read-only sqlite URI `file:<path>?mode=ro`).
* Queries Alpaca read-only (GET) for every candidate entry order; an order
  that cannot be found leaves the row untouched (never an invented fill), a
  partially filled order is left to the runner.
* Idempotent: a second run finds nothing to do.
* Uses the same terminal handling as change 3 (`lpr.mark_entry_canceled`).

## 5. Terminal exit/stop statuses + P&L from filled_qty

* `reconcile_exit_orders` now writes the broker's terminal status
  ('canceled' / 'cancelled' / 'expired' / 'rejected') into the orders row
  instead of leaving it 'submitted'.
* The realized P&L of a closed position uses the exit order's `filled_qty`
  when the broker provides one (fallback: the position qty).

## Risks / decisions

- A canceled entry with a partial fill keeps the filled shares; the rest of
  the order is gone. The stop is placed for the filled quantity only.
- `mark_entry_canceled` refuses to touch a row that is no longer
  'pending_fill', so a position that already opened is never wrongly closed.
- The runner's own sleeve accounting (open notional + pending entry notional)
  stays inside the 15% sleeve after a cancellation (proven by test).
- No strategy parameter changed: SLEEVE_EQUITY_FRAC=0.15, MAX_POSITIONS=3,
  MAX_POSITION_PCT=0.10, ATR_MULT=3.0, TIME_STOP=10 are untouched.
